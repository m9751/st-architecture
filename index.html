SmokinTerritory Architecture Reference

INTERNAL v2026-04-22 Michael Busacca · Enterprise AE, MuleSoft Healthcare · Salesforce

1 Architecture Overview

SmokinTerritory is a territory intelligence platform built to surface the right healthcare accounts at the right time for MuleSoft pipeline generation. It combines a Supabase PostgreSQL data warehouse (865 accounts, 469 unique parent organizations), a Vercel-hosted dashboard, GitHub Actions signal pipelines, and a Claude Code AI layer with 18 enforcement hooks, 5 specialist agents, 73+ skills, and 14+ MCP server connections — all coordinated to reduce pipeline research from hours to minutes.

The architecture has three layers: a compute layer (Vercel for frontend/APIs, GitHub Actions for pipeline orchestration, Railway for persistent services), a data layer (Supabase for structured CRM data, Qdrant for vector search, Hindsight for cross-session AI memory), and an AI infrastructure layer (Claude Code orchestrating specialized agents via hooks, skills, and MCP tools). A fully isolated second Supabase project (Whiskey Down) handles trading/backtesting workloads with a hard zero-cross-join boundary.

Six scoring engines — TYS v7.4, CHPS v1.1, BHPS v1, PSPS v1.4, RMS v1, and Golden Record v2 — produce tier assignments and composite scores that drive account prioritization, campaign sequencing, and proposal routing.

2 System Layers

Three-layer architecture: compute services expose data and APIs; the data layer persists and indexes everything; the AI layer orchestrates intelligence on top.

3 Data Flow

Territory intelligence flows left-to-right: raw signals collected from external sources → enriched and stored in signal_events → scored and tiered by 6 engines → surfaced through the Brief API and dashboard → routed into campaign outreach.

6 AI Infrastructure

The Claude Code AI layer is built from four components: enforcement hooks that physically gate bad actions, specialist agents that handle parallel workloads, skills that encode deep domain knowledge, and MCP servers that connect to every external system.

Enforcement Hooks (18)

Hooks run at PreToolUse, PostToolUse, SessionStart, and SessionEnd. They block patterns — not just advise against them. Registered in ~/.claude/settings.json. Deployed via make install from ~/repos/claude-config/.

plan-gate.sh
Blocks all mutations (Edit/Write/Bash/MCP) while in Plan Mode. Prevents blocked-tool loops.
no-guess-gate.sh
Blocks Supabase/Vercel/edge-function mutations unless a prior read was logged via breadcrumb.
exchange-first-gate.sh
Blocks MuleSoft code creation without a prior Exchange search breadcrumb.
obsolete-scoring-gate.sh
Blocks deprecated scoring column names (v5.5.0 era). Pattern-matches on file content at PreToolUse.
delivery-checklist-gate.sh
Breadcrumb-based gate. Blocks declaring "done" without Supabase deliverables log. Fail-open.
config-sync.sh
Auto-mirrors skill/memory edits to ~/repos/claude-config GitHub repo at PostToolUse.
pipeline-f-weekly.sh
Sunday 22:00 cron. Self-learning pattern detection across session history (115 patterns, 7 rules).
config-sync-cron-win11.sh
30-minute bidirectional sync between ~/.claude/ and GitHub. Windows scheduled task.
skill-router-gate.sh
At UserPromptSubmit: scores catalog.json against prompt, injects top-3 skills when score ≥ 25.
no-guess-breadcrumb.sh
Companion to no-guess-gate. Stamps breadcrumb after any Supabase/Vercel read.
pipeline-f-status.sh
SessionStart: surfaces Pipeline-F run status, recurring patterns, and consolidation candidates.
pipeline-f-mirror.sh
Mirrors pipeline-f output to ~/repos/claude-config/pipeline-f/ for cross-device access.

HARD RULES — Never violate:

1. Never cross the streams. SmokinTerritory tables must never be queried from a Whiskey Down task and vice versa.

2. No cross-project SQL joins. Zero dblink, zero foreign data wrapper, zero table references across project IDs in any SQL statement.

3. WD_ prefix enforces project routing. Any code referencing WD_SUPABASE_URL or WD_SUPABASE_KEY operates on Whiskey Down ONLY.

4. Never dual-write. If a WD build row is found on SmokinTerritory (legacy error), migrate it to the WD project then DELETE the SmokinTerritory row.

5. Ambiguous task? ASK Michael which project — never guess.
